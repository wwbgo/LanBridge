# LanBridge · 局域桥

一个聚焦 **Windows 宿主机 → Hyper-V / WSL2 / Docker / Podman 服务** 的开源端口转发工具。C# / .NET 10，原生 WinUI 3 中文界面，独立后台进程，TCP / UDP，MIT 许可。

> 初版目标是把少量映射管理好，不是 VPN、SSH 隧道或公网穿透。应用层转发不加密，也不会把客户端原始源 IP 透明保留到目标。

## 使用方式

完成打包后，运行 `artifacts\LanBridge-single\app\LanBridge.App.exe`。界面按需启动同目录的后台程序。关闭窗口会隐藏到通知区域，托盘和端口转发继续运行；托盘菜单“打开主界面”可恢复窗口，“退出 LanBridge”会停止当前用户后台并退出应用，同时保留规则供下次启动恢复。首次启动没有示例规则，也不会默认开放任何端口。

新增规则时填写：

| 字段 | 含义 |
|---|---|
| 名称 | 例如“虚拟机 Web” |
| 协议 | TCP、UDP 或 TCP/UDP（同一条规则同时监听两种协议），需与真实服务一致 |
| 监听地址 | Windows 宿主机的局域网 IP；`127.0.0.1` 仅本机可访问 |
| 监听端口 | 局域网设备访问的宿主机端口 |
| 目标地址 | 宿主机能够访问的虚拟机 IP 或主机名 |
| 目标端口 | 虚拟机中的服务端口 |

例如，**假设**宿主机为 `192.168.1.100`，虚拟机服务为 `172.25.80.10:8080`：

```text
局域网设备 → 192.168.1.100:18080 → LanBridge → 172.25.80.10:8080
```

这些地址只是示例，不是对你的实际网络的检测结果。目标服务必须监听虚拟机网卡地址或全部地址，不能仅监听虚拟机的 `127.0.0.1`。

### WSL2、Docker 与 Podman

目标发现运行在当前登录用户的界面进程，不让 SYSTEM 服务执行用户的 Docker/Podman/WSL 配置。发现仅辅助填写当前地址与端口；保存后的规则仍为普通 TCP/UDP 映射，暂不自动跟踪重建后的 IP 或端口。

Docker 与 Podman 使用同一个 **Docker / Podman** 发现入口，合并和去重已发布端口；WSL2 入口不进入容器运行时专用发行版。容器未发布的端口不是程序故障：只汇总提示，不伪造 Windows 主机映射。

| 来源 | 转发路径与限制 |
|---|---|
| WSL2 | Windows 监听端口 → 运行中发行版地址和服务端口。镜像网络或 localhost 转发可用时也可手动填写 `127.0.0.1`；NAT 地址变化后需重新发现。不会自动启动已停止的发行版。 |
| Docker Desktop / 本机 Docker | Windows 监听端口 → 已发布到 Windows 的主机端口，例如 `127.0.0.1:8080`。不直接把 Linux 容器的内部 IP 当作 Windows 可达地址。未发布端口需先自行调整容器配置。 |
| Podman | 优先使用已发布且能够确认属于本机 Podman machine 的主机端口。不把远程连接的端口误认为 Windows 本机端口。无法确认时提示手动输入可达地址。 |

发现不到 CLI、运行时未启动、权限不足和远程上下文都应给出说明；仍可手动添加 Windows 能连接到的地址。不会自动安装、启动、重建容器或修改网络配置。若容器已在 Windows 的 `0.0.0.0:8080` 发布，则该端口可能已经对局域网开放；不要再创建指回同端口的转发回环。

支持“转发到一个宿主机可达端点”不等于绕过 WSL/容器网络隔离。真正未发布、且 Windows 无路由直达的容器服务，需要用户先提供可达路径。UDP 同样要求运行时真正发布 UDP 端口，不会以 TCP 测试冒充 UDP 可达。

### 状态与诊断

- **监听中**只表示宿主机端口绑定成功，不保证虚拟机服务在线。
- TCP 目标测试可以验证 TCP 建连；不能证明 HTTP 身份认证、业务状态或 UDP 服务可用。
- UDP 没有通用的“建连成功”信号，需要使用真实协议客户端检验。
- Hyper-V 查询使用桌面程序自身权限，不复用旧后台的安全令牌。权限不足时先从托盘退出，再以管理员身份打开；也可加入 Hyper-V 管理员组后重新登录。本程序不会自动提权或更改用户组。
- Hyper-V 默认交换机的来宾地址可能变化。首版不承诺自动跟踪地址，地址变化后需更新规则。
- 不要把高权限数据库、管理端口直接暴露到不可信网络。

## 防火墙与权限

**运行应用不会自动开放防火墙，不会安装服务，不会弹出提权。** 若 Windows 防火墙阻止局域网入站连接，需要由管理员明确放行。

管理员可以审查并使用 `scripts\Set-LanBridgeFirewall.ps1`。脚本限制为专用网络、局域网来源、指定地址、端口和协议；只会删除带有 LanBridge 所有权标记且名称匹配的规则。替换已有规则前需明确移除旧规则。

```powershell
# 在管理员 PowerShell 中执行；先将 ID、地址和端口替换为自己的真实值。
# 可先加 -WhatIf 审查计划操作。
.\scripts\Set-LanBridgeFirewall.ps1 `
  -RuleId '11111111-1111-1111-1111-111111111111' `
  -ListenAddress '192.168.1.100' -Port 18080 -Protocol TCP -WhatIf
```

不要为了调试关闭整个防火墙。公共网络配置不会被此脚本放行；应先确认该网络确实可信。防火墙脚本不属于 UI 自动动作。

可选 Windows 服务由 `scripts\Install-Service.ps1` 明确安装；使用前请审查脚本和管理员权限要求。服务模式必须将可执行文件部署到受保护的目录，不能让系统服务执行普通用户可改写的开发目录文件。普通后台模式的生命周期与用户登录会话有关；需要机器开机即恢复时再采用服务模式。

## 开发

- Windows 10/11 x64，推荐 Windows 11。
- .NET SDK 10.0.403 或兼容的 10.0 servicing SDK。
- WinUI 3 / Windows App SDK（NuGet 锁定版本由 App 项目声明）。
- Visual Studio 的 Windows 应用开发工具链；部分工具通过 NuGet 恢复。

```powershell
.\scripts\Build.ps1
.\scripts\Package.ps1
```

无论代码构建还是测试都不应隐式修改系统防火墙或安装服务。

### 项目结构

```text
src/LanBridge.Core       TCP/UDP 引擎、规则验证、原子配置保存
src/LanBridge.Control    本机命名管道客户端与共享协议
src/LanBridge.Host       独立后台进程 / Windows 服务
src/LanBridge.App        WinUI 3 中文界面
src/LanBridge.Discovery  当前用户的 WSL / Docker / Podman 只读目标发现
tests/                  自动化测试与黑盒验收
scripts/                构建、打包、显式安装及防火墙辅助工具
```

管理接口不监听 HTTP 端口。命名管道应只允许当前用户、SYSTEM 与本机管理员；服务安装时明确配置可管理它的用户 SID。运行目录和日志路径见程序状态。

## 验收边界

自动化测试应覆盖真实 loopback TCP/UDP、半关闭、规则启停、配置损坏与恢复，以及后台进程重启。**本机测试不能证明另一台局域网设备经真实防火墙访问 Hyper-V 来宾成功**；实际部署还需要做这一项端到端验收。

## 发布与升级

正式发行版见 [GitHub Releases](https://github.com/wwbgo/LanBridge/releases)。Windows x64 提供：

- `LanBridge-Setup.exe`：当前用户安装程序，无需安装系统服务。
- `LanBridge-win-x64.zip`：便携包，完整解压后启动 `LanBridge.App.exe`，不要只复制 EXE。
- `SHA256SUMS`：安装包及便携包的 SHA-256 清单。

### 维护者发布

使用严格的 `v主版本.次版本.修订号` tag（例如 `v0.1.0`）发布稳定版。版本号同时写入 App、Host 和安装程序。

```powershell
# 在确认代码及验证结果已提交后执行；不要重用或移动已发布 tag。
git push origin main
git tag -a v0.1.0 -m "LanBridge 0.1.0"
git push origin v0.1.0
```

GitHub Actions 在 Windows runner 上运行测试、构建、打包，并将安装包、便携包和校验清单上传到同一 Release。构建或测试失败时不会发布正式版。工作流本身使用仓库的 `GITHUB_TOKEN`，不需要额外保存个人令牌。运行结果请以仓库 Actions 页面为准，本地构建成功不等于远程发布成功。

### 应用内检查与升级

点击主窗口的 **检查更新**（无需先选择规则或连接后台）。应用只查询本仓库最新的稳定 Release，并显示当前/目标版本、发布说明和升级方式；不会后台静默安装。

1. 点击“下载更新”，下载官方 HTTPS 资产，校验 `SHA256SUMS` 及 GitHub 提供的 SHA-256 digest。
2. 确认升级。助手先校验并准备文件，收到后台正常退出确认后才获得安装授权；应用退出后才替换文件。
3. 便携模式默认使用 ZIP，先备份应用文件，复制失败时回滚，成功后重新打开。失败恢复材料和日志位于 `%LOCALAPPDATA%\LanBridge\updates\`。
4. 已安装版默认打开普通安装向导，目标为当前应用目录。也可选择便携 ZIP。安装向导会创建卸载项和快捷方式，**安装向导不承诺事务回滚**，中途失败可能需要重新运行安装程序修复。

首次正式 Release 尚未发布时，应用无法提供可下载更新；网络故障、API 限流和缺失校验文件不应被解释为“已是最新版”。升级会短暂停止当前用户的端口转发；不会安装服务、改变防火墙，也不会启动 WSL、容器或虚拟机。规则和日志保留在用户数据目录，而非发布文件夹。SHA-256 校验用于发现下载损坏，不等同于独立的代码签名或发布者认证。

初版不提供公网穿透、客户端源 IP 保留、驱动层透明代理，或无权限情况下自动读取所有虚拟机。
